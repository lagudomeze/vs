# UX 审查（RUN v1）：reference roguelike 玩家坐下来的前三分钟

> 审查对象：**feat/ux-review** @ **c22b23d** + **docs/RUN_V1.md**（设计分支 **vx-tactical**，2026-10-22 版）
> 说明：本分支代码仍是实时三人小队原型，RUN 尚未实现；本文以 RUN_V1、现有 3D 截图和 reference roguelike 操作习惯为审查对象，不把推断写成实测。实时版审查见 **docs/UX_REVIEW.md**。
> 结论：方向正确，但当前 HUD/相机/键位/名字牌都是实时小队遗产，RUN 需要的是一次减法重构；最大的风险不是内容量，而是格子、回合、目标、意图四件事没有“一眼可懂”的定义。

## 0. 结论先行

reference roguelike 玩家会在前三分钟做这些事：小键盘/vi 移动、撞墙、撞怪、按 1、按 5、按 >、按 x、按 I/C、死亡后按 R。RUN_V1 目前只完整回答了“撞怪”和“按 I/C 存在”，其余要么没定义，要么和 reference roguelike 肌肉记忆冲突。

五个 P0：

1. **格子与回合不可一眼看懂**：没有网格/脚底格，没有回合归属/先攻条，自由旋转让 13×13 的方向感更差。
2. **天赋目标选择不成立**：所有技能都用“最近敌人/朝向格”，火球 AoE 和闪现传送无法成立。
3. **HUD 还是实时小队**：队伍/波次/自动攻击/FPS 必须删，单角色卡/楼层卡/天赋栏/日志没有位置。
4. **敌人意图与危险提示不足**：只有目标名字和血条，没有“它下回合打哪/打多少/会不会多打一次”。
5. **中文新 UI 会缺字**：本分支字体 112 字形，RUN 抽检 91 个词条有 75 个词条缺字、113 个字符缺失；回合/天赋/背包/角色/楼层都会变方框。

3D 模型本身不是问题；问题是 3D 的透视、自由旋转、模型尺度和名字牌在 13×13 格子上会互相打架。下面按 reference roguelike 玩家的实际动作顺序写。

### reference roguelike 玩家的前 3 分钟脚本

| 玩家动作 | reference roguelike 预期 | RUN_V1 设计 | 体验风险 |
| --- | --- | --- | --- |
| 小键盘 8/2/4/6 或 hjklyubn | 8 向移动，一步一回合 | 只写 WASD 4 向 | 肌肉记忆失效；斜向缺失 |
| 撞墙 | 不消耗回合 + 明确反馈 | 不消耗回合 | 没有反馈→以为输入丢了 |
| 撞怪 | 普攻、伤害数字、日志 | 撞敌人 = 普攻 | 需要命中/伤害/朝向反馈 |
| 按 1 | 进入目标模式，范围/AoE 预览，确认/取消 | “最近敌人/朝向格” | 火球/闪现不可控 |
| 按 5 或 . | 等待一回合 | 有“等待”动作，无键位 | 不能安全等冷却 |
| 按 > / < | 上下楼 | 走 stairs 自动下一层 | 误触、漏 loot |
| 按 x 或悬停 | 查看敌人/地形 | 未定义 | 不知道敌人抗性/技能 |
| 按 I / C | 背包/角色，暂停 | 有键位，无布局 | 找不到，或挡住战场 |
| 死亡 | 死亡回顾 + 快速重开 | 只有 R | 不知道为什么死 |

## 1. 格子与回合：能不能一眼看懂

**直接回答：按当前设计不能。** 不是 3D 模型的问题，而是格子/回合还没有变成可见的 UI 对象。

### 1.1 当前证据

- 现有 3D 截图里没有任何格子边界，只有激活/目标环；角色/敌人的位置靠影子、地砖缝和名字牌猜。**critic_window.png** 中“狂战士 12”和“骷髅兵”名牌已经叠在一起；**orbit.png** 旋转 60° 后没有任何方向提示。
- 13×13 格在 480 宽内，满宽也只有 **36.9px/格**，边缘透视后更小；一块 3 个汉字的 12px 名牌约 39px，加 8px 内边距就是 47px，**比一格还宽**。所以“每个敌人挂名字”在 480 下必然重叠。
- RUN_V1 §4 定义了回合/速度，但 §9 只在顶部中央写“回合提示/危险提示”，没有指定“你的回合/敌人行动”的状态、回合数、先攻顺序或输入锁。
- 当前相机是自由 yaw（Q/E 连续旋转、右键拖拽），RUN 需要格子方向感；自由旋转会让 W 的世界方向随相机变化，13×13 的方位记忆被打断。

### 1.2 必须补的四层

1. **地面网格**：1px 低对比格线/地砖倒角，不是霓虹棋盘；可走/阻挡/危险格用底色区分；鼠标/键盘悬停格加亮；移动路径和技能范围用同一套格子语法。
2. **脚底格**：每个 actor 一个 0.9 格圆环；玩家金色实心环 + 朝向楔形；敌人红色细环；精英双环；Boss 1.1 格环 + 尖刺；当前目标用四角括号，不要和脚底环同形。现有“激活金环/目标红环”只靠颜色区分，在 3D 透视里不够。
3. **相机 90° 吸附**：只允许 0/90/180/270 四个 yaw，Q/E 或拖拽后 0.2s 吸附到位；右上角常驻“北”指针；默认 0°。旋转不消耗回合。不要保留 60° 这种中间角度做战术视角——格子会变菱形，WASD 会失去“上=北”的直觉。
4. **回合状态**：顶部常驻一条：**你的回合 17** / **敌人行动** / **等待输入**；建议放进角色卡或独立 130×18 状态条，不要和顶部中央的目标/危险卡抢位置。敌人回合锁输入，只给当前 actor 0.12s 插值动画；8 个敌人要在 1s 内演完；按住空格/右键可快进。先攻条显示接下来 3–5 个 actor，速度 ≥150 的敌人加 **×2** 标记；否则“速度”是不可见属性。

### 1.3 验收

- 5 名 reference roguelike 玩家，30 秒内 5/5 能指出自己的格子和相邻四格。
- 20 次移动中 ≥18 次落在预期格；旋转 90° 后再走 20 次，错误 0。
- 任意时刻 5/5 能说出“现在是谁的回合”；8 敌回合 <1s，无输入被吃掉。
- 5/5 能说出下一个行动的敌人和它是否会连续行动两次。
- 名字牌重叠不超过 1 秒（见 P1-7）。

## 2. 移动、碰撞、攻击反馈

**直接回答：规则有了，反馈没定义。** 撞墙/撞怪在 3D 里很容易被误读为“输入丢了”。

- **撞墙**：不消耗回合是对的，但必须有反馈：角色轻微前顶/回弹 0.08s、短音效、日志“墙挡住了”，否则玩家无法区分“没消耗回合”和“按键没收到”。
- **撞怪**：播放攻击而非移动，角色自动面向目标，伤害数字 + 命中闪白 + 日志。撞怪时不要先插值到敌人格再弹回。
- **移动**：逻辑立即结算，Transform 0.12s 插值到格心；到达后脚步/尘土；如果目标格被 actor 占据，直接转为攻击；如果被墙/障碍挡住，不消耗回合。
- **4 向还是 8 向**：13×13 上 4 向可读性更好，但 reference roguelike 玩家会先按斜向。v1 可以保留 4 向，但必须：帮助里写“4 方向”、支持方向键/小键盘 8/2/4/6、不要画出斜向路径；若要贴近 reference roguelike，8 向是 P1。
- **等待键**：必须有 5 或 .（以及一个可点的“等待”按钮）；否则玩家只能靠撞墙/来回走等冷却，这会制造无意义输入。
- **输入锁**：敌人回合中不接受移动/技能，或只接受 1 个缓冲并在敌人回合结束后执行；绝不能连按两次走出两格。快进时也要保持“一回合一次行动”。

验收：撞墙 20 次，20 次都有反馈且回合数不变；撞怪 20 次，20 次都造成伤害并写日志；敌人回合中连按 10 次方向键，敌人回合结束后最多移动 1 格；按 5 能安全过一回合。

## 3. 敌人意图与危险提示

**直接回答：不够。** 目前只有目标名字/血条，预计伤害还是“可选”。

RUN_V1 §7 只写“目标格高亮/箭头；攻击前显示预计伤害（v1 可选）”。对 reference roguelike 玩家，这不够：回合制里最贵的信息是“我走过去会不会被打、打多少、会不会被多打一次”。

建议最小意图集：

| 敌人状态 | 显示 | 位置 |
| --- | --- | --- |
| 近战相邻 | 攻击图标 + 目标格箭头 + 预计伤害 | 敌人头顶/脚底 |
| 远程且 LOS | 射线 + 命中格 + 预计伤害 | 敌人到目标格 |
| 移动 | 小箭头 + 目标格 | 敌人脚底 |
| 等待/被阻挡 | … / ? | 敌人头顶 |
| 速度 ≥150 | ×2 徽章 | 先攻条/头顶 |
| Boss AOE | 受影响格红/橙底 + 范围轮廓 | 地面 |
| 未看见 | ?，不显示意图 | 不剧透 |

另外：

- **危险格预览**：玩家把光标移到目标格时，显示“如果走到这里：2 个敌人可攻击，预计 -14 HP”，并把受威胁格加红色斜线。这个功能比“伤害数字”更能减少“走一步就死”的挫败。
- **目标卡**：顶部中央 130×30 显示名字/HP/意图；等级、抗性、天赋进查看模式，不要全塞进卡片。
- **查看模式**：x 或鼠标悬停查看敌人六属性/天赋/抗性/状态；reference roguelike 玩家会用这个做决策。
- **危险分级**：普通/精英/Boss 用体型 + 轮廓 + 颜色三重区分，不要只靠红色；色盲下也能分辨。
- **信息边界**：只对可见/相邻敌人显示意图，未见敌人显示 ?；远程 LOS 被墙挡住时显示“视线被挡”，不要给出假射线。

验收：5/5 能说出相邻敌人的下回合动作；10 次攻击预告的伤害误差 ≤1；Boss AOE 提前 1 回合标出受影响格；没有“没有预警的 AOE”导致死亡。

## 4. HUD：单角色，三层信息

**直接回答：旧 HUD 必须整块删，不能只换文案。**

### 4.1 旧 HUD 必须删

| 旧元素 | 尺寸/占屏 | 为什么必须删 |
| --- | --- | --- |
| 队伍面板 | 234×82 / 14.8% | 单角色；三行队友、12级、> 都不再成立 |
| 状态面板 | 170×82 / 10.7% | 波次/余敌/视角/帧率/三角；RUN 没有波次、没有实时相机数据 |
| 操作面板 | 206×82 / 13.0% | 8 条实时键位，含 F 反制、TAB 切换、F1/ESC；RUN 键位不同 |
| 标题技术 | 178×53 / 7.3% | 引擎信息；应让位给角色/回合 |
| 技能行/击杀/12级 | — | 自动战斗/小队遗产；RUN 用天赋栏和击杀日志 |

旧 HUD 合计 45.9%；RUN 的目标应该 ≤30%。**删掉这四个面板，比加任何新面板都重要。**

旁证：vx-dungeon 的 HUD shell（5d58567）仍保留标题/操作/队伍三个面板（新增了时间状态/日志行），四面板结构没有变。RUN 不能沿用这个壳。

| 区域 | 尺寸 | 占屏 |
| --- | --- | ---: |

建议坐标：角色 (6,5)、目标 (175,5)、楼层 (344,5)、日志 (6,206)、天赋栏 (165,214)。比旧 HUD 少 19 个百分点，且多出回合、资源、天赋、楼层、日志五类 RUN 必需信息。注意日志只常驻 3 行（12px 字模 + 15px 行距），L 打开 20 行完整日志；RUN_V1 §9 的“最近 5 条”在 480 下会占 75px 高，不建议照搬。

### 4.3 层级

| 层级 | 信息 | 位置 |
| --- | --- | --- |
| L1 | 当前 HP/资源、回合数、1/2/3 是否可用、当前目标 | 左上/顶部中央/底部 |
| L2 | 楼层/剩余敌人/楼梯方向、目标意图、日志、状态 | 右上/目标卡/左下 |
| L3 | 六属性/装备/天赋详情、帮助、相机、种子 | I/C/H，不常驻 |

一个可执行规则：**同一屏只有一个金色标题**（当前角色名）；楼层/目标/日志标题都用 muted，避免四个面板抢焦点。旧 HUD 四个金色标题是它“像仪表盘”的主要原因。

### 4.4 天赋栏、资源、冷却

- 3 个槽 + 1 个普攻槽；每槽 40×40（3× 下 120×120），显示：1 键、图标、技能名、消耗、冷却回合、不可用原因。
- 冷却用**回合数**，不要转圈动画：**重击 · CD 3**、**冲锋 · 就绪**、**战吼 · 精力不足 12/20**。reference roguelike 玩家会按回合算，不会按秒算。
- 资源条必须有数字 18/30 和每回合回复 +2/回合；只画条无法做取舍。
- 不可用状态用灰 + 文字原因，不只变暗；色盲/低对比下仍能读。
- 选中的天赋在天赋栏上方显示一行说明（范围/伤害/状态），不要弹浮动 tooltip 挡战场。
- 1/2/3 在背包里用于装备/使用物品，属于模态上下文；打开背包时必须在标题写“背包（1/2/3 装备）”，避免和战斗热键混淆。

验收：5/5 能说出每个槽的消耗、冷却和为什么不可用；10/10 次冷却回合数与实际可再用回合一致；资源不足时按 1 有明确提示，不静默。

### 4.5 背包 / 角色面板

- I：3 个装备槽（主手/身体/饰品）+ 8 格背包列表；选中显示属性、对比（绿/红 delta）、1/2/3 装备/使用、Esc 关闭；打开不消耗回合，关闭回到原状态。
- C：六属性、派生（HP/资源/攻击/护甲/暴击/速度）、装备、天赋、状态；不要和背包重复。
- 拾取：g 或自动拾取，二选一并在帮助写明；g 更贴近 reference roguelike，自动拾取更少操作；无论哪种，都要有“获得 铁剑”日志和 3 秒 toast。
- 地面掉落/宝箱要有地面光圈或颜色，不能只靠 3D 小模型在墙边被挡住。
- 不要做全屏模态遮住战场；半屏/底部抽屉更适合 480，且保留“我现在在哪”的空间感。

验收：5/5 能在首次掉落后 30 秒内打开背包并装备；装备后 HP/攻击 delta 在 0.5 秒内可见；打开/关闭不消耗回合、不丢输入；掉落不会消失。

### 4.6 中文与字体

本分支 src/core/cjk_font.zig 只有 112 个字形。抽检 91 个 RUN 常用 UI 词条：

- **75 个词条至少缺 1 字，113 个字符不在子集里**。
- 回合、天赋、精力、法力、悖论、背包、角色、装备、楼层、楼梯、宝箱、死亡、速度、意图、危险、施法、命中、闪避、护甲、经验、升级、品质、普通、稀有、史诗、属性、力量、敏捷、体质、感知、意志、等待、传送、眩晕、燃烧、中毒、视野、路径、房间、墙壁、地面、选择、职业、开始、游戏、继续、日志、敌人、剩余、下一层、失败、暂停、设置、音量、全屏、按键、说明、帮助、确认、取消、对比、丢弃、使用、物品、药水、金币、等级、法力值、精力值、悖论值 都不在全字库。
- 缺字会画成 9×8 方框，不会崩溃；RUN 的新 HUD 会直接变成方框墙。
- 数字仍是 5×7 ASCII，和 12×12 中文基线不一致；回合数/HP/资源/冷却都是关键数字，不能继续用小号 ASCII。

验收：所有 UI 字符串 0 缺字；zig build test 有缺字扫描；480 与 1440 下 5/5 能读 HP/资源/回合/冷却；关键数字高度 ≥12px。

## 5. 3D 模型在格子上的可读性

**直接回答：模型能读，格子不能读。** 需要脚底格、90° 相机和遮挡处理。

现有 3D 模型本身很好看，但格子战术需要额外约束：

- **模型尺度**：普通 actor 的视觉占地 ≤0.85 格，Boss ≤1.15 格；脚底环 0.9 格。当前 Boss 模型 scale 1.95，放到 13×13 会视觉压住相邻格；名字牌/血条不能跟着模型变大。
- **朝向**：脚底环加 90° 楔形箭头；转身 0.12s；不要只靠角色脸/武器判断朝向。当前模型在 40° 俯视下能看出正反面，但混在三人/多怪里不够。
- **遮挡**：相机与玩家之间的墙/柱子做 0.15s 淡出或剖切；被墙挡住但已见过的敌人显示轮廓/红色描边；目标格和当前目标永远不被墙挡住。orbit.png 里旋转后墙体仍会切掉左侧视野，格战术会更明显。
- **名字牌预算**：非目标敌人不显示名字，只显示血条/血点；目标显示名字/等级/意图。3 个汉字名牌 = 47px > 一格，不能每只怪都挂。
- **楼梯/宝箱**：地面图标 + 3D 道具双重标记；楼梯在楼层卡显示方向；宝箱有金色地面光圈。否则 3D 小模型在墙边会被完全遮住。
- **相机**：90° 吸附 + 北向指针（同 §1）；不要用 60° 旋转做“更好看”的构图，格子会变菱形。
- **缩放**：13×13 需要比当前 8.2 的距离更远或更俯视；建议默认 dist 9.5–10.5、pitch 45–50°，让 13 行都能落在 270px 内；用 --dist 做可读性测试。

验收：5 分钟内名字牌重叠 ≤1 次/秒；5/5 能在旋转 90° 后指出北/东/南/西；5/5 能看见被墙部分遮挡的敌人轮廓；Boss 的脚底格仍清晰；楼梯/宝箱在 3D 场景中被 5/5 找到。

## 6. 死亡、重开、楼层推进、节奏

**直接回答：目前只有“全灭/R”，没有死亡回顾、楼梯确认和时长目标。**

### 6.1 死亡与重开

- 死亡画面至少给：到达楼层、等级、回合数、击杀、死因（最后一击来源/伤害类型）、装备摘要；R 重开同职业 / Esc 退出。
- 不加确认框；reference roguelike 玩家接受死亡，但要知道为什么死。当前实时版只有“全灭 / R 重开”，不够。
- 重开 <2 秒；职业选择可以记住上次；不要在死亡和重开之间插动画。

验收：5/5 能说出死因和到达楼层；R 后 2 秒内可操作；死亡画面不残留战斗 HUD。

### 6.2 楼层推进

- **不要走上去自动下楼**。reference roguelike 玩家习惯 >；自动下楼会让人误触、漏宝箱、来不及看层结算。站在楼梯上显示“按 > 下一层”，> 确认；Esc 取消。
- 每层进入时给 2 秒层卡：第 1 层 · 遗忘地窖 + 敌人数 + 楼梯方向；不要用实时版那种 2.6 秒“第1波来袭”横幅。
- 楼层卡常驻右上：第1层/3 · 敌3 · 楼梯↘；楼梯方向如果随相机旋转，要用“北”而不是固定箭头。
- 清层条件要明确：是“敌人清空才开楼梯”，还是“随时可下、鼓励探索”？建议 v1 允许随时下楼，但楼层卡显示剩余敌人；否则玩家会在空层里找最后一个怪。
- 3 层通关；Boss 第 3 层。Boss 前给一次明确提示（门/层卡/音乐），不要只是“又一个怪”。

验收：0 次误触下楼；5/5 知道当前层/剩余敌人/楼梯方向；每层进入 2 秒内知道目标；清层后 5/5 知道可以下楼。

### 6.3 节奏目标

RUN_V1 没有给时长目标；建议 v1 用：

| 指标 | 目标 |
| --- | --- |
| 单层 | 3–5 分钟 |
| 整局（3 层） | 10–15 分钟 |
| Boss 战 | 1–3 分钟 |
| 首次死亡 | 第 2 层前后 |
| 重开 | <2 秒 |

理由：13×13、4–8 敌人/层，探索 + 战斗 + 捡装备，3–5 分钟/层是合理切片；10–15 分钟一局适合 roguelike 的“再来一局”。reference roguelike 本体更长，但 v1 是垂直切片，不需要用垃圾怪填充到 30 分钟。

验收：10 次 auto/人工跑局中位 10–15 分钟；每层 3–5 分钟；首次玩家第 1 层死亡率 <20%、第 2–3 层有死亡；重开 <2 秒。

- **问题**：RUN_V1 要“左下最近 5 条日志”，但在 480 下 5 行 12px 字 + 15px 行距约 75px 高，会占掉 28% 屏高；状态效果（减速/眩晕/燃烧）没有图标/回合数；伤害数字仍是 5×7 小字 + 偏移阴影，浅色地砖上对比不足。
- **证据**：RUN_V1 §9（日志 5 条）；当前分支 HUD 没有日志字段/渲染（hud.zig）；伤害数字 5px；面板内对比过关，但世界内红/金约 2.0/1.2:1。
- **建议**：常驻 3 行日志 + L 展开 20 行；颜色区分伤害/治疗/状态/掉落，最新一行高亮；状态图标 8×8 + 剩余回合数，悬停/查看显示说明；伤害数字 2× + 完整 1px 描边/深色底板；伤害类型颜色（物理白、火焰橙、冰霜青、时空紫）在日志和数字上一致。
- **验收标准**：5/5 能在 1 秒内找到最近一次命中/受伤；减速/眩晕等状态 5/5 能说出剩余回合；世界内伤害数字对比 ≥4.5:1；日志不遮挡天赋栏；L 能看 20 行。

## 8. 这轮不要做什么

- 不要为了“像 reference roguelike”先做 8 向、天赋树、随机词缀；先把 4 向 + 3 天赋 + 3 层跑通。
- 不要保留任何队伍/波次/自动攻击 HUD；它们是实时原型的遗产，不是 RUN 的基线。
- 不要用自由旋转相机做“更好看”的展示；RUN 的格子方向感优先于构图。
- 不要在字体缺字、目标选择、敌人意图没做对之前截宣传图；这些会直接放大成“方框 + 乱打”。
