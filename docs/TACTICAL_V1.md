# Aether Keep: Tactical v1 — 设计基线

> 目标：在现有 VX（Zig 0.17 + SDL3 + zflecs，真 3D 像素竞技场）上，把 voxelith 文档里最有价值的“时间/行动/威胁/属性/物品/内容化”机制落成一个可玩完整版，而不是改成体素/2D 等距。

## 1. 定位

一句话：三个职业守住浮空竞技场；玩家不动时世界暂停，一动/一施法时间才流动；敌人的重击在生效前亮出来，世界为玩家停下，可以抢先打断；装备、属性和战利品让每一局有变化。

保留：真 3D 网格、固定俯视可旋转相机、480×270 像素渲染、中文 HUD、5 波竞技场。
吸收：时间属于玩家、行动前摇/后摇、威胁可见、反制/打断、六属性、装备/物品、内容数据化、战斗日志。
不做：体素世界/挖掘/放置、2D 等距图块、格子移动、开放世界大地图、多人。它们会推翻现有 3D 渲染与 PR1/PR2 的基础。

## 2. 设计支柱

1. 时间属于玩家：空闲时逻辑时间冻结；行动/威胁才推进。
2. 威胁看得见就能抢先：敌人重击有前摇和可读的威胁条；暂停给出一次反制窗口。
3. 一次只做一件事：移动与技能互斥；起手可被移动取消，代价不退。
4. 数值可追溯：面板/日志能说清来源；属性 = 基础 + 装备/增益修正。
5. 内容靠数据长：技能/敌人/物品先走数据文件；加内容不改系统代码。

## 3. 时间模型

三种状态，互斥：

| 状态 | 进入条件 | 逻辑时间 | 玩家可做 |
| --- | --- | --- | --- |
| 冻结 Frozen | 无玩家行动、无威胁 | 0 | 选目标、看面板、决定下一步 |
| 流动 Flowing | 玩家移动/施法中，或敌人行动未威胁玩家 | fixed_dt | 移动/施法/取消 |
| 威胁 Threat | 有敌人重击瞄准玩家，且尚未结算 | 0 | 反制（F）、移动、做别的（视为放弃） |

- 仿真用 logical_dt（固定 1/60），表现（相机/粒子/UI 动画）用 real_dt。
- 不能只传 dt=0：用显式 TimeMode gate 所有战斗系统；零 dt 下不得触发冷却/DoT/AI 攻击。
- 空闲冻结时，AP/HP 回复、状态计时、粒子仍用 real_dt？规则：战斗资源/状态用 logical_dt，纯表现用 real_dt。
- 威胁暂停时，玩家可以移动（放弃反制、敌人照常结算）或按 F（进入反制）。

## 4. 行动模型

ActionState（每个英雄/敌人一个）：

    phase: Idle | Windup | Recovery
    remaining: f32
    action_id: u32
    effect_fired: bool
    kind: u8
    snapshot: { damage, cost, cast_time, cooldown, potency, target }

- 释放：校验 → 同步扣费 + 起冷却 → 生成 Action → Windup。
- Windup 结束：触发恰好一次效果；进入 Recovery（冷却/后摇，不锁移动）。
- 玩家移动：取消当前 Windup（代价/冷却不退）；Recovery 不取消。
- 一次只做一件事：新技能取消旧 Windup；输入缓冲 0.15s。
- 敌人普通攻击保持简单；重击/技能走 ActionState，打上 Threat。

## 5. 威胁与反制

- Threat { source, target, action, potency, kind }：敌人重击生成 Action 时登记。
- 有 Threat 指向玩家 → 进入 Threat 模式，时间冻结，HUD 顶部出提示。
- F 反制：消耗 20 精力/AP，短暂前摇后比较 player.interrupt_power vs threat.potency；
  - 成功：删除敌人 Action（敌人仍在，代价不退）；
  - 失败/未反制：敌人 Action 照常结算。
- 反制是通用能力；伙伴也自动反制（简单 AI），玩家反制优先。
- 视觉：敌人头顶红色蓄力条 + 目标脚下红环；HUD 顶部“⚠ 骷髅兵正在蓄力 — F 打断”。

## 6. 属性、装备、物品

六属性：力量、敏捷、体质、感知、魔力、意志。避免每个属性一个泛型组件：用 Stats 结构 + StatKind 枚举 + Modifier 列表。

派生（v1）：
- HP 上限 = 40 + 体质×8 + 装备
- AP/精力上限 = 60 + 意志×4 + 装备
- 攻击 = 基础 + 力量/敏捷/魔力（按职业）
- 护甲 = 体质×0.5 + 装备
- 暴击 = 5% + 感知×0.5%（上限 50%）
- 移速 = 3.0 + 敏捷×0.01（上限 4.2）

装备槽：头/身/手/腿/脚/饰品 + 主手/副手。v1 先做主手、身、饰品三个，降低 UI 复杂度；数据模型预留 6 槽。
- 物品定义：id、名称、槽位、品质、flat/pct 修正、描述。
- 掉落：敌人死亡掉 1 件（30%），自动进背包；I 打开背包，数字键装备/卸下；装备立即重算。
- 词条：v1 只做固定词条，不做随机词缀（参考设计的搁置项）。

## 7. 成长与内容

- 击杀获得 XP；升级 +1 属性点（v1 自动按职业分配，HUD 显示）。
- 5 波 + 每波精英/第 5 波 Boss；波次间恢复。
- 内容数据：assets/data/enemies.json、items.json、skills.json，启动时 @embedFile 加载 + 校验；加载失败回退到内置默认并报错（CT-05/06 的简化版）。
- 战斗日志：左下角最近 5 条（伤害/掉落/打断/升级），可追溯。

## 8. UI/UX

- 底部：三英雄状态（HP/AP/等级）、当前技能/冷却、装备摘要。
- 左上：标题/时间状态（冻结/流动/威胁）。
- 右上：操作提示（WASD、空格技能、F 反制、I 背包、Tab 切换）。
- 顶部中央：波次/威胁提示。
- 敌人：目标名牌 + 血条 + 蓄力条；非目标只显示细血条。
- 背包/角色面板：半屏，I 切换；显示六属性、装备、最近战利品。
- 中文文案沿用 Ark Pixel 字体；新增字符重新生成字形。

## 10. 完成定义（v1）

- [ ] 空闲冻结、移动/施法推进、威胁暂停三种状态可观察。
- [ ] 技能有前摇/结算/冷却；移动取消；费用不退。
- [ ] 敌人重击可被 F 反制；成功/失败都有日志与反馈。
- [ ] 六属性/装备/掉落生效，面板可查。
- [ ] 5 波可通关；失败/胜利/R 重开。
- [ ] 中文 UI 完整；新增字符无缺字。
- [ ] zig build test 通过；headless 自动跑完一局；窗口截图。
- [ ] QA 回归清单 + 批评者 UX 报告。

## 11. 团队与迭代

- Lead：设计/架构/集成/HUD/最终验收。
- 程序 A：时间与行动。
- 程序 B：属性/物品/内容加载。
- 美工：敌人/道具/UI 视觉与截图。
- QA：测试矩阵、自动跑局、数值指标。
- 批评者：每轮看截图/试玩，按体验优先级提意见。

迭代顺序：行动/时间 → 威胁/反制 → 属性/装备 → 掉落/成长 → UI/UX → 内容/平衡。
